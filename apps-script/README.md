# 규칙 일꾼 (두두 고객장부)

설계 정본은 `80_브랜드마케팅/주문고객_설계.md`, 순서는 `주문고객_진행표.md`. 이 폴더는 공개 사이트에 내보내지 않는다(`_config.yml` 제외).

- `Code.js` — 장부 구조(SCHEMA)·기본값과 자동 처리 전부. 구글 시트 「두두 고객장부」에 붙인 Apps Script 프로젝트에 그대로 넣는다.
- `appsscript.json` — 시간대 Asia/Seoul, V8, 웹 앱(실행 = 대표, 누구나 호출).
- `test/run.html` — 가짜 데이터 시험. 미리보기 서버로 `/apps-script/test/run.html` 을 열면 결과가 나온다. 실제 개인정보를 넣지 않는다.

## 장부에 붙이는 법(처음 한 번)
1. 「두두 고객장부」 → 확장 프로그램 → Apps Script. `Code.gs` 내용을 지우고 `Code.js` 를 붙여 넣는다. 프로젝트 설정에서 시간대 Asia/Seoul.
2. `setup` 실행 → 권한 허용. 머리줄이 설계와 다르면 멈춘다.
3. `installTriggers` 실행 — 10분마다 `runScheduled`.
4. 웹 앱 배포는 4-2단계(홈페이지 주문서)에서 한다. 배포 주소는 공개돼도 되지만 장부 링크는 대표만.

## 무엇을 하나
| 함수 | 하는 일 |
|---|---|
| `intake(p)` / `doPost` | 접수 기록 → 고객 찾기·만들기(연락처 기준) → 동의·취향 → 주문이면 확정 시도, 아니면 관심. 같은 연락처·같은 원문 10분 안이면 중복. 연락처 없으면 확인필요. order 스위치가 꺼져 있으면 주문도 문의로 받는다 |
| `confirm_` | 남은 양 − 예약된 양, 작업 달력(도정 가능·하루 최대량)을 보고 확정 또는 대기. 확정 때 예약·배정, 금액·단골 할인, 받을 날, 입금 기한, 두두 ○호 |
| `processWaitlist` | 대기 주문을 들어온 순서대로 다시 확정 시도 |
| `checkDeadlines` | 입금 기한이 처음 지나면 안내 1회·기한 연장, 다시 지나면 자동 취소·재고 복귀 |
| `setStatus(번호, 상태)` | 입금·작업·발송·도착·취소. 발송 때 남은 양 차감, 도착 때 예상 소진일. 작업 뒤 취소는 확인필요 |
| `updateStages` | 관심 → 첫 고객 → 단골 → 쉬는 고객, 식당·가게·단체는 따로 |
| `refillAlert` | 예상 소진일 며칠 전 한 번 |
| `send_` | 연락 규칙·문자틀대로 연락 시트에 남김. 광고는 소식 동의·시간대·월 상한·수신 거부·선물 받는 분을 거른다. 실제 발송은 6단계 |
| `exportSwitches` / `doGet?action=switches` | 스위치와 공개 곡식(숨김 제외), live_stock 이 켜지면 남은 양 |
| `runScheduled` | 위 예약 일들을 돌리고 설정 `last_run` 에 시각 |

- 문자틀은 전부 「【임시】」 — 4-2단계에서 문안(3단계)으로 바꾼다.
- 할인율(`loyalty_rates`)·가격·작업 달력·재고는 시험값이거나 비어 있다. 대표가 정한 값을 장부에 넣는다.
- 입금 대조(Gmail)·발송 서비스·카톡 챗봇은 6단계.
