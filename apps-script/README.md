# 규칙 일꾼 (두두 고객장부)

설계 정본은 `80_브랜드마케팅/주문고객_설계.md`, 순서는 `주문고객_진행표.md`, 문자틀·연락 규칙은 `홈페이지_문안.md` 부록. 이 폴더는 공개 사이트에 내보내지 않는다(`_config.yml` 제외).

- `Code.js` — 장부 구조(SCHEMA)·기본값과 자동 처리 전부. 구글 시트 「두두 고객장부」에 붙인 Apps Script 프로젝트에 그대로 넣는다.
- `appsscript.json` — 시간대 Asia/Seoul, V8, 웹 앱(실행 = 대표, 누구나 호출).
- `SelfTest.js` — 실제 구글 환경 시험(임시 시트를 새로 만들어 그 위에서만). 편집기에서 `selfTest` 실행.
- `test/run.html` — 가짜 데이터 시험. 미리보기 서버로 `/apps-script/test/run.html` 을 열면 결과가 나온다. 실제 개인정보를 넣지 않는다.

## 지금 붙어 있는 곳 (2026-11-08)
대표 계정 Apps Script 「두두 고객장부 규칙 일꾼」(장부에 붙인 프로젝트가 아니라 따로 만든 프로젝트 — `BOOK_ID` 로 장부를 엶). 파일 Code.gs(= Code.js)·SelfTest.gs. 권한 허용·10분 예약 작업 걸림. 코드를 고치면 편집기의 Code.gs 를 이 파일로 바꾸고 저장한다.

## 장부에 붙이는 법(처음 한 번)
1. 「두두 고객장부」 → 확장 프로그램 → Apps Script(대표가 직접 클릭 — 앱 브라우저는 클로드 클릭으로 새 창을 열지 않는다). `Code.gs` 내용을 지우고 `Code.js` 를 붙여 넣는다. 프로젝트 설정에서 시간대 Asia/Seoul.
2. `setup` 실행 → 권한 허용(대표). 머리줄이 설계와 다르면 멈춘다.
3. `installTriggers` 실행 — 10분마다 `runScheduled`.
4. 웹 앱으로 배포 → 주소를 `assets/order-config.js` 의 `endpoint` 에 넣으면 홈페이지 보내기 단추가 열린다. 배포 주소는 공개돼도 되지만 장부 링크는 대표만.

## 무엇을 하나
| 함수 | 하는 일 |
|---|---|
| `intake(p)` / `doPost` | 접수 기록 → 고객 찾기·만들기(연락처 기준) → 동의 → 장바구니 품목이면 조합 저장 후 주문(확정 시도) 또는 문의(관심). 대량 상담(kind=bulk)은 관심·고객 유형만, 자동 문자 없음. 같은 연락처·같은 원문 10분 안이면 중복, 연락처 없으면 확인필요. order 스위치가 꺼져 있으면 주문도 문의로 |
| `confirm_` | 곡식마다 남은 양, 쌀은 작업 달력(도정 가능·하루 최대량)까지 보고 확정 또는 대기. 금액 = 곡식(가격 원/kg × kg) + 소포장 − 할인 + 배송비 |
| 할인 `discount_` | ○호 고객(전체 첫 `ho_seats`명, 첫 주문 확정 순) 모든 주문 `ho_rate`% · 아니면 소식 동의가 살아 있을 때 `loyalty_every`번째마다 `loyalty_rate`% — 둘은 겹치지 않음, 기준은 곡식+소포장 |
| `processWaitlist` | 대기 주문을 들어온 순서대로 다시 확정 시도(확정되면 「대기확정」) |
| `checkDeadlines` | 입금 기한이 처음 지나면 「입금독촉」·기한 연장, 다시 지나면 자동 취소·재고 복귀 |
| `setStatus(번호, 상태)` | 입금·작업·발송·도착·취소. 발송 때 남은 양 차감, 도착 때 예상 소진일. 작업 뒤 취소는 확인필요 |
| `handleFeedback` · `optOut` | 밥맛 답(1·3 → 다음조합, 4 → 대표 직접 전화) · 「그만」(동의 철회·수신 거부·결과 알림) |
| `updateStages` | 관심 → 첫 고객 → 단골 → 쉬는 고객, 식당·가게·단체는 따로 |
| `send_` | 문자틀·연락 규칙대로 연락 시트에 남김. 안내는 「[두두농장]」·꼬리, 광고는 「(광고)」·수신거부. 광고는 소식 동의·시간대·월 상한·수신 거부·선물 받는 분을 거르고, 시간대 밖 안내는 「대기: 시간대」로 두었다 보냄. 필수 값(계좌 등)이 비면 「확인필요」. 실제 발송은 6단계 |
| `exportSwitches` / `doGet?action=switches` | 스위치·공개 곡식(숨김 제외)·남은 ○호 자리, live_stock 이 켜지면 남은 양 |
| `recall` / POST `{kind:'recall', tel}` | 지난 조합·회차·소식 동의 여부·○호만(이름·주소 없음). 번호마다 한 시간 `recall_per_hour`번. 번호는 주소(URL)에 싣지 않는다 |
| `millDate_` | 홈페이지 도정일 — 작업 달력에서 `min_mill_kg` 자리가 남은 가장 가까운 날(`switches` 답의 `millDate`). 확정 때 배정과 같은 규칙 |
| `lookup` · `cancelMine` · `pauseMine` / POST `{kind:'lookup'|'cancel'|'pause', tel, no}` | 내 주문(/doodoo/my/). 휴대폰 번호 + 주문번호가 맞아야 함, 틀리면 번호마다 한 시간 `lookup_fail_per_hour`번. 받는 분은 이름 첫 글자·시·군만. 취소는 도정 전(접수·대기·확정·입금)만 → 재고·작업 달력 복귀·「취소확인」(입금 전이면 환불 문장 뺌)·대기 다시 봄. 멈춤은 주문 「정기」 칸을 「멈춤」으로 |
| `scheduleRegular` | 정기 주문(「정기」 Y)이 도정 뒤면, 다음 도정일 `regular_ahead_days`일 전에 정기로 고른 곡식만 같은 조합으로 새 주문·확정. 앞 주문은 「이어짐」 |
| `purgeTest` | 시범 운행 정리 — 「시험」 Y 인 접수·고객·주문과 그 고객의 동의·취향·관심·연락·처리 기록을 지움. 확정분은 먼저 취소해 재고·작업 달력을 되돌린다. 편집기에서 실행 |
| `syncTemplates_` (setup 안) | 문자틀 문구를 문안 부록 1과 같게(상태 칸은 그대로). 머리줄 끝에 새 칸(정기·시험)이 생기면 칸만 채운다 |
| `onBookEdit` | 대표가 장부 「재고」「작업 달력」을 고치는 순간 대기 주문을 다시 확정 시도(10분 기다리지 않음). 규칙 일꾼이 쓴 칸으로는 불리지 않는다 |
| `runScheduled` | 입금 기한 · 대기 · 늦어짐 감지 · 도착 뒤(다음 날·밥맛·단골축하) · 정기 다음 예약 · 단계 · 떨어질 때쯤 · 동의 2년 확인 · 시간대 대기분, 설정 `last_run` |
| `doPost` 주문 | 장부 `order` 스위치가 꺼져 있으면 `{ok:false, closed:true}`(예약 문의 모드 없음). `test:true` 시험 주문만 받아 「시험」 표시 |

| 결제 `stockCheck` · `checkout` · `payConfirm` · `payAbort` · `depositCallback` / POST `{kind:'stock'|'checkout'|'pay-confirm'|'pay-abort'}`, 토스 웹훅 | 주문서 진입 때 남은 양 확인(1) → [결제하기] 때 다시 확인(2)·자리 잡기·금액 확정(결제대기) → 토스 결제창 → 승인 API(카드·간편결제·휴대폰 = 입금 / 가상계좌 = 확정 + 계좌 안내) → 가상계좌 입금 웹훅(DEPOSIT_CALLBACK, 승인 때 받은 `secret` 대조) → 입금. 결제창에서 안 돌아오면 `pay_hold_minutes` 뒤 자리 풀기, 가상계좌 기한이 지나면 바로 자동 취소 |
| 고객 취소 `customerCancel_` | 도정 전 = 토스 결제 취소까지 자동. 휴대폰 결제 달 넘김·가상계좌 입금 뒤(환불 계좌 필요)·토스 취소 실패 = 「확인필요」(대표 직접) |
| 회원 `sendCode` · `verifyCode` · `join` · `login` · `resetPw` · `member` / POST `{kind:'code'|'verify'|'join'|'login'|'reset'|'member'}` | 인증번호 6자리·3분·하루 5번(해시만 저장), 비밀번호 소금 + SHA-256 1,000번(원문 없음), 5번 틀리면 10분 잠금, 로그인 표(토큰)는 해시만 「로그인」 시트·30일. 마이페이지: me·정보 수정·로그아웃·탈퇴·주문 취소·정기 멈춤/주기·지난번과 같게 |

### 스크립트 속성(프로젝트 설정 > 스크립트 속성 — 대표가 넣음, 코드·저장소에 없음)
- `TOSS_SECRET_KEY` — 토스페이먼츠 결제위젯 시크릿 키(`test_gsk…` → 계약 뒤 `live_gsk…`).
- `TEST_MODE` — `on` 일 때만 홈페이지 요청의 `test`(시범 운행 표시·가짜 결제 키 mock_·화면에 인증번호)를 받아 준다. 시범 운행이 끝나면 지운다.
- 토스 개발자센터 웹훅에 웹 앱 주소를 넣고 `DEPOSIT_CALLBACK` 을 켠다. ★Apps Script 웹 앱은 POST에 302로 답해 토스가 「실패」로 보고 다시 보낼 수 있다(처리는 한 번만 됨) — 전송 기록에서 확인.
- 결제 수단 순서·기본 선택(무통장 입금(가상계좌) · 카드 · 간편결제 · 휴대폰, 계좌이체 끔)과 가상계좌 입금 기한은 토스 결제 어드민에서 정한다(코드로 못 정함).

- 문구를 바꿀 땐 문안을 먼저 고치고 장부 「문자틀」을 맞춘다.
- 가격(곡식 시트)·배송비·계좌·작업 달력·재고는 비어 있다. 대표가 정한 값을 장부에 넣는다(홈페이지 쪽은 `assets/order-config.js`).
- 입금 대조(Gmail)·발송 서비스·카톡 챗봇은 6단계.
